## U-021 — reviewer agents cite rule 9 rather than restating it

- **Applies to:** running. **Supersedes U-002**, whose remedy widens the
  copy this entry removes.
- **Change:** a reviewer agent no longer carries its own enumeration of
  the gated set. It cites `CLAUDE.md`'s rule 9 as the only copy of the
  boundary, and adds on top only what rule 9 cannot say: that a
  subagent, having no exchange in which to be gated, treats everything
  merely *gated* as forbidden outright — the gate is the operator's
  authorisation in an exchange, and a subagent has none.

  U-002 was right that the enumeration must be the whole gated set
  rather than the deny list, and wrong about where the enumeration
  should live. Two instantiated agents that each carried their own copy
  were measured drifting apart inside a single step, which is the
  failure a second copy always eventually produces; and a probe
  confirmed `CLAUDE.md` reaches a subagent's context, so the copy is
  avoidable. Widening a copy makes it longer and no less stale.
- **Detect:** a reviewer agent that enumerates forbidden commands, or
  carries a never-run list, instead of citing rule 9; or two agents
  whose enumerations differ from each other or from `CLAUDE.md`.
- **Remedy:** replace each enumeration with the citation plus the
  subagent clause. In the same pass, **probe that `CLAUDE.md` actually
  reaches a subagent's context** — one exchange with any agent, asking
  it to quote rule 9's opening line — and record the result with the
  project's other measured permission behaviour. The citation assumes
  it; if the probe comes back negative, report that rather than
  proceeding, because an agent that can reach neither the copy nor the
  original has no boundary at all. While in those files, correct the
  `tools:` lists to tools that exist in the version you run: a name
  Claude Code does not define is dropped silently, so a list can
  advertise capability the agent does not have.
