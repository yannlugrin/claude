# Doctrine changes — 2026-08-14

One entry: the Bash permission guard becomes a shipped template instead of
something each project invents. Format and pass procedure:
[../updates.md](../updates.md).

## U-020 — the Bash guard is a template, and it reshapes `settings.json`

- **Applies to:** running (new handoffs ship it from the assets directory
  without a pass)
- **Change:** the second layer of the permission boundary — the
  `PreToolUse` hook that catches what a permission pattern cannot express
  — is now a proven template, `bash_guard.py`, instantiated as
  `.claude/hooks/bash_guard.py`. It is an engine plus a per-project
  `REGISTRY`, and only the registry is edited: the engine decides on
  *parsed* argv, one subcommand at a time, walking through environment
  assignments, wrappers, a shell's `-c`, `eval` and unquoted
  substitutions, so a gated act is caught wherever its deciding token
  sits. Per tool, the enumeration goes on whichever side is finite —
  `rules` for tools that are safe by default with a listable set of
  dangerous acts (git, docker), `grants` for tools that are dangerous by
  default with a small provable safe set (deploy tooling, an `rm`
  restricted to a disposable state root). Its `GIT` entry is ground
  rules, identical across projects, added to for a stated project reason
  and never weakened.

  It changes `.claude/settings.json` as much as it changes the hook: one
  **broad allow per registry tool**, replacing the long enumerated allow
  list; **no `ask` rule for any tool the guard gates**, since a matching
  ask prompts even where the hook returns allow and so cancels every
  carve-out; **no prefix rule restating a guard decision**, a prefix
  being strictly weaker (`Bash(git push:*)` misses `git -C dir push`) and
  a second source of truth; and a short **`deny` backstop for the
  unrecoverable acts**, which the broad allow makes necessary — a hook
  fails open, and under a broad allow a dead hook costs an unprompted
  `git push --force` rather than an extra prompt. For the same reason
  `bash_guard.py --selftest` belongs in whatever runs before a commit,
  and a rule with no `CASES` entry fails it.

  The reasoning is measured, not theoretical. Hand-written guards drift
  into matching raw command strings: one project's guard passed
  `git commit -m x \` + newline + `--amend` because it tokenized per
  line, and denied `rm ../other-project` outright although no allow rule
  matched it — leaving the operator no way to approve what a prompt would
  have offered. Both classes disappear when the decision is made on
  parsed argv, and the template carries its own cases proving they stay
  gone.
- **Detect:** a bespoke `PreToolUse` Bash hook matching the raw command
  string with regexes or prefixes; or no hook at all, with the boundary
  carried by a long enumerated allow list; or a `settings.json` whose
  `ask` tier restates what a hook already decides; or a guard with no
  selftest wired into the project's pre-commit gate.
- **Remedy:** copy the template from the handoff assets directory (or
  from a project already on it), then **port the intent, not the
  implementation** — re-express each existing rule in the registry model
  and name any that cannot be expressed, rather than translating regex to
  regex. Classify each tool as `rules` or `grants` and say which and why;
  add a `CASES` entry per rule; rewrite `settings.json` to the pairing
  above, with a line on each removed permission entry; wire the selftest
  into the lint; delete the old hook and every reference to it, including
  the project's own notes on how permissions work there — a document
  describing the replaced mechanism is the easiest staleness to miss.
  **The permission baseline is never within latitude:** the whole
  registry and the settings diff go to the user in a single review pass.
  After that pass the rules are frozen in the template's own sense —
  every later addition, change or deletion needs the user's agreement,
  and a guard misbehaviour they report is fixed only together with a
  `CASES` entry reproducing the exact command they gave.
